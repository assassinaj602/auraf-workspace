# AURAF Shared Data Contract (M2 Interface Specification)

This document serves as the **immutable data contract** between Muhammad Hammas Rasheed and Muhammad Assad Ullah. By adhering strictly to the field names, data types, SQLite column names, and CSV headers defined below, both developers can write and test code independently on separate laptops without interface mismatches or merge conflicts.

---

## 1. `DeviceState` Schema

Represents the physical, computational, and environmental state of the client device captured at inference scheduling time.

| Field Name (Dart Model) | Dart Type | SQLite Column Name | Unit / Allowed Values | Description |
| :--- | :--- | :--- | :--- | :--- |
| `timestamp` | `int` | `timestamp` | Epoch milliseconds (`ms`) | System timestamp when state was captured. |
| `batteryLevelPercent` | `int` | `battery_level_percent` | `0` to `100` (%) | Current state of charge of the device battery. |
| `batteryCurrentMa` | `double` | `battery_current_ma` | Milliamperes (`mA`) | Instantaneous discharge current (negative if discharging, positive if charging). |
| `temperatureCelsius` | `double` | `temperature_celsius` | Degrees Celsius ($^\circ C$) | Device battery or skin thermal sensor reading. |
| `availableRamMb` | `double` | `available_ram_mb` | Megabytes (`MB`) | Total unreserved system memory available to the app. |
| `peakMemoryMb` | `double` | `peak_memory_mb` | Megabytes (`MB`) | Peak resident memory allocated by the application during execution. |
| `networkCondition` | `String` / `Enum` | `network_condition` | `'stable'`, `'high_latency'`, `'intermittent'`, `'offline'` | Current network state classification. |
| `contextSizeTokens` | `int` | `context_size_tokens` | Non-negative integer | Total token count of the incoming prompt context. |
| `remainingBudgetUsd` | `double` | `remaining_budget_usd` | US Dollars (`$USD`) | Remaining monetary budget allocated for cloud inference queries. |

### Network Condition Enum Values:
- `'stable'`: High bandwidth, low latency (<50ms RTT), 0% packet loss (e.g. strong Wi-Fi / 5G).
- `'high_latency'`: Stable bandwidth, high latency (200ms - 500ms RTT), simulated cellular/satellite.
- `'intermittent'`: Jittery latency with 5% - 20% packet loss.
- `'offline'`: Zero network connectivity (0 kbps).

## 2. `CandidateAction` Schema

Represents an inference execution decision generated by the Lyapunov Drift-plus-Penalty optimizer or benchmark permutation.

| Field Name (Dart Model) | Dart Type | Allowed Values / Format | Description |
| :--- | :--- | :--- | :--- |
| `contextBudgetTokens` | `int` | `512`, `2048`, `8192` (or arbitrary token limit) | Target token budget after context compression/pruning. |
| `placement` | `String` / `Enum` | `'cloud'`, `'device'` | Execution target destination. |
| `modelId` | `String` | `'gemini-1.5-flash'`, `'gemma-2-2b'`, `'phi-3-mini'`, `'qwen-2.5-1.5b'` | Target model identifier. |
| `quantization` | `String` | `'none'`, `'int8'`, `'int4'`, `'fp16'` | Quantization precision applied to on-device weights. |
| `threadCount` | `int` | `1`, `2`, `4`, `8` | Number of CPU/NPU inference threads allocated. |

## 3. `BenchmarkRecord` (Unified Telemetry & Benchmark Output)

Each benchmark iteration produces a single `BenchmarkRecord`. This structure defines the columns for both the local SQLite database and the exported CSV file.

### Column Mapping Specification

| Index | Field Name (Dart) | SQLite Column Name | SQLite Data Type | CSV Header Name | Unit / Range | Description |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `runId` | `run_id` | `TEXT PRIMARY KEY` | `run_id` | UUID / String | Unique identifier for benchmark run. |
| 2 | `timestamp` | `timestamp` | `INTEGER NOT NULL` | `timestamp` | Epoch ms | Execution start timestamp. |
| 3 | `deviceModel` | `device_model` | `TEXT NOT NULL` | `device_model` | String | Device name (e.g., `Pixel_7_Android_14`). |
| 4 | `networkCondition` | `network_condition` | `TEXT NOT NULL` | `network_condition` | String | `'stable'`, `'high_latency'`, etc. |
| 5 | `contextBudget` | `context_budget` | `INTEGER NOT NULL` | `context_budget` | Tokens (`int`) | Evaluated context size (e.g., `512`, `2048`, `8192`). |
| 6 | `placement` | `placement` | `TEXT NOT NULL` | `placement` | String | `'cloud'` or `'device'`. |
| 7 | `ttftMs` | `ttft_ms` | `REAL NOT NULL` | `ttft_ms` | Milliseconds (`ms`) | Time To First Token. |
| 8 | `totalLatencyMs` | `total_latency_ms` | `REAL NOT NULL` | `total_latency_ms` | Milliseconds (`ms`) | End-to-end inference turnaround time. |

## 4. SQLite DDL Schema (Hammas Copy-Paste Reference)

Hammas should use this exact SQL table creation statement inside `packages/auraf/lib/src/logging/`:

```sql
CREATE TABLE IF NOT EXISTS benchmark_records (
    run_id TEXT PRIMARY KEY,
    timestamp INTEGER NOT NULL,
    device_model TEXT NOT NULL,
    network_condition TEXT NOT NULL,
    context_budget INTEGER NOT NULL,
    placement TEXT NOT NULL,
    ttft_ms REAL NOT NULL,
    total_latency_ms REAL NOT NULL,
    tokens_per_sec REAL NOT NULL,
    energy_mah REAL NOT NULL,
    peak_memory_mb REAL NOT NULL,
    temp_celsius REAL NOT NULL,
    cost_usd REAL NOT NULL,
    quality_score REAL NOT NULL,
    constraint_violated INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_records_timestamp ON benchmark_records(timestamp);
CREATE INDEX IF NOT EXISTS idx_records_placement ON benchmark_records(placement);
CREATE INDEX IF NOT EXISTS idx_records_network ON benchmark_records(network_condition);
```

## 6. Model Serialization Key Guidelines

When Assad implements `packages/auraf/lib/src/models/`, the serialization methods will expose the exact JSON/Map keys corresponding to the SQLite column names:

- `toMap()`: Returns a `Map<String, dynamic>` where keys match the **SQLite column names** above.
- `fromMap(Map<String, dynamic> map)`: Deserializes from database rows using identical keys.
- `toCsvRow()`: Formats values into a comma-delimited string matching the strict 15-column order.
